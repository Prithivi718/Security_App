RESET TOKEN VALIDATION
--------------------------------------------------

The desired UX is:

→ frontend reads reset token
→ frontend validates token with backend
→ token valid
→ reveal New Password + Confirm Password
→ user submits
→ password reset
→ navigate to login

POST /auth/reset-password/validate

    token
}

Response:
{
    valid: true
}

The current backend service already validates the token when resetPassword() is called, but it does not currently expose a separate pre-validation operation. If this endpoint is not implemented, clearly mark it as a backend dependency rather than inventing client-side validation.
